# Several units go up in one answer

The same review found nothing that said whether separate approval units may
stand in one answer, what a bare yes to such an answer approves, and which file
state the check of a later unit reads. A correction beside an extension, a
formatting passage, several drafts of one session and "delete A, B, C" each let
the agents split: one can show everything and write on one yes, another ask unit
by unit.

`global.md` now lets several units go up in one answer, each marked. A yes takes
all of them unless I name one, and each is checked as the ones before it will
have landed. In the draft skill the names passed after the check's closing quote
now count for every draft file the same yes writes, and not only for a
supersede's successor. The drafts a supersede repoints go up in the supersede's
answer, each as its own unit.

This is a successor to ADR 0024 on one point. 0024 rejected folding the
dependents into the supersede's yes, because each is a judgement per file. That
judgement stays: each dependent is its own marked unit and a no reaches it
alone. What changed is that the yes to the answer is no longer the yes to one
unit.

## Considered Options

**One unit after another (rejected).** Every yes then answers exactly one
change, and every check reads the disk. It was rejected because a supersede with
two dependents costs three rounds of question and answer for what one look
settles.

**Keeping the dependents after the supersede's write (rejected).** It keeps
0024's order, where the check reads the successor off the disk. It was rejected
because the passed names already cover a file that the same yes writes, so the
order was an exception with no reason left.

## Consequences

- A bare yes approves more than before. Naming one unit is how I refuse it.
- A no still stops every draft that depends on the refused one.
